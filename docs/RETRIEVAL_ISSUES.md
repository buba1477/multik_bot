# 📋 RETRIEVAL ISSUES — проблемы retrieval и что с ними делать

## Проблема 1: NEGATIVE_PATTERNS ловит легитимные вопросы

**Симптом:** Запросы «Имеет ли право… не относится…?» или
«…за исключением…» могут попадать в NEGATIVE-контур и получать
компактный ответ без источников — хотя вопрос требует перечисления.

**Причина:** NEGATIVE_PATTERNS в `engine_rag.py` проверяют вхождение
подстроки без контекста. «Не относится», «не является», «кроме»,
«исключением», «за исключением» — все могут быть частью запроса.

**Что делать:** ✅ **СДЕЛАНО.** Избыточные паттерны удалены.
Текущий набор из 5 паттернов — минимальный.

**Риск:** Низкий. False positives не задокументированы.

**Статус:** ✅ **Закрыто**
**Источник:** `engine_rag.py` стр.341–347, ROOT_CAUSE_TABLE раздел 6.

## Проблема 3: Лексический разрыв (разговорное → юридическое)

**Симптом:** «Подрабатывать по совместительству» → чанк «выполнять иную
оплачиваемую работу». BM25 (стемминг) не матчит.

**Причина:** QUERY_REPLACEMENTS содержит лишь 22 замены. Многие
разговорные слова из 84 FZ-потерь не заменяются.

**Что делать (по приоритету):**

1. **Топ-5 частых пар** (50/84 инстанций):
   - все вариации `инспектор/сотрудник [ФНС]` → `гражданский служащий`

2. **Средней частоты** (2–4 инстанции):
   - `подрабатывать` → `выполнять иную оплачиваемую работу`
   - `уволить` → `увольнение в связи с утратой доверия`
   - `сдать 3-ндфл / 3-ндфл` → `налоговая декларация`
   - `рабочее время` → `служебное время`
   - `назначить своего сына` → `близкое родство или свойство`
   - `субсидию на оплату жилья` → `единовременная субсидия на приобретение жилого помещения`
   - `поведение` → `служебное поведение`
   - `фирме` → `коммерческая организация`
   - `разглашение` → `служебная информация`

3. **Слабые/неприменимо:**
   - `брак с иностранным гражданином` → не чистая подстановка
   - `материальная помощь` → нет в GT-чанке
   - `продаю машину` → кросс-морфология (уже в проде)

4. **Синхронизировать eval** (Проблема 2) добавит `ндс`, `ндфл`, `машину`,
   `машина`, `усн`.

**Риск:** Средний. Широкие замены («сотрудник» → «гражданский служащий»)
могут менять смысл вне домена госслужбы. Рекомендуются фразовые ключи.

**Статус:** 🔴 **Открыто**
**Источник:** `/tmp/final_synonym_report.json`, анализ 2026-11-02.

## Проблема 8: Классификатор (complex_exact) — не проблема, реранкер компенсирует

**Симптом:** Опасение, что классификатор направит казуистические запросы (complex_exact)
в dense-контур, где гибрид 0.5/0.5 даёт Hit@5 ниже чистого dense (0.759 vs 0.821).
На complex_exact (112 запросов) гибрид 0.5/0.5 проигрывает dense −5.3 п.п.

**Причина:** BM25 привносит лексику (хорошо для STRONG/citation), но «разбавляет»
dense-ранжирование на казуистике, где dense сам справляется.

**Проверка:** После реранкера (bge-m3, pool=30) гибрид обгоняет dense:

| Режим | Hit@5 | R@5 | nDCG@10 |
|---|---|---|---|
| Dense (реф.) | 0.821 | 0.732 | 0.690 |
| Hybrid 0.5/0.5 | 0.768 | 0.652 | 0.619 |
| **Hybrid 0.5/0.5 + Rerank** | **0.866** | **0.727** | **0.678** |

Reranker подтягивает релевантные чанки в топ-5: +9.8 п.п. Hit@5 (от hybrid без реранка)
и +4.5 п.п. (от чистого dense). Классификатор не нуждается в правке.

**Статус:** ✅ **Закрыто — не проблема**
**Источник:** `eval/eval_complex_hybrid_rerank_gpu/eval_report.json` vs
`eval/research_complex_hybrid/eval_report.json`; METRICS_SUMMARY.md разбивка по подгруппам.

**Что делать (дорого, отдельный проект):**
1. **Query expansion** — 2–3 юр. формулировки на каждый запрос (hand-crafted).
2. **Fine-tune FRIDA** с hard-negative mining (частичное решение).
3. **BM25-синонимы** — добавить в индекс альтернативные формулировки
   (в т.ч. из ручных подстановок Problem 3).

**Риск:** **Высокий.** Без query expansion или fine-tune не решается.
9.8% = 11 запросов — small-tail, но каждый такой запрос даёт пользователю
«ничего не найдено».

**Статус:** 🔴 **Открыто (низкий приоритет — дорого)**
