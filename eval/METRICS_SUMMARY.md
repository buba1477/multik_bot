# Метрики RAG-поиска: обоснование архитектуры

## Методология

Мы замерили **7 конфигураций** на двух чистых датасетах:
- **USER (77 вопросов)** — абстрактные, смысловые вопросы («Какая мера является профилактикой коррупции?»).
- **EXACT (147 вопросов)** — точные реквизиты («117-ФЗ статья 217», «пункт 4 статьи 346.13»).

Все замеры проведены офлайн (без внешних API) на GPU (GTX 1660 Ti, rerank batch=4),
retrieval — Qdrant (CPU, как в проде). Корпус: 5446 чанков.

## Условия эксперимента

- **Дата замеров:** 28 октября 2026 г.
- **Модель эмбеддингов (Dense):** FRIDA (Sber RoSBERTa) — `hf_cache/FRIDA`.
- **Модель реранкера (Cross-encoder):** `BAAI/bge-reranker-v2-m3`.
- **Векторная база:** Qdrant (`fns_collection`, 5446 чанков).
- **Железо:** GPU GTX 1660 Ti (для реранка, batch=4); retrieval — CPU (как в проде).

## Выводы (почему так)

### 1. USER (абстрактные вопросы) → **DENSE (1.0 / 0.0)**
- **Hit@5 = 88.1%** — лучший результат среди всех конфигураций.
- **Время ответа: ~50 мс** (мгновенно).
- **Почему не Hybrid?** `hybrid_rerank` даёт `Hit@5 = 86.8%` (даже чуть хуже), но работает **20 секунд**. Разница в точности в пределах погрешности, а в скорости — в 400 раз.
- **Вердикт:** DENSE — быстрее, проще, и не хуже по качеству.

### 2. EXACT (точные реквизиты) → **HYBRID 0.5/0.5 + reranker**
- **Hit@5 = 86.2%** (против 73.8% у чистого DENSE).
- **Прирост: +12.4%** (каждый 8-й пользователь получает ответ, который иначе бы не получил).
- **Почему не DENSE?** DENSE проваливается на точных номерах статей (он плохо ищет «117-ФЗ статья 217»).
- **Почему не чистый BM25?** BM25 даёт `Hit@5 = 54.5%` (он ловит только цифры, но не смысл).
- **Вердикт:** HYBRID + reranker — единственный способ вытащить нормативные вопросы на 86% Hit@5.

### 3. Адаптивный классификатор
`classifier.py` автоматически определяет тип запроса и переключает режимы:
- Если USER → DENSE (50 мс).
- Если EXACT → HYBRID + reranker (20 сек, но точнее).

**Итог:** у нас не «компромисс», а **два оптимальных режима под два типа задач**.
